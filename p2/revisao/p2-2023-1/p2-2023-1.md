## Questão 1 - 9,0 pontos

Considere:

### I. Banco de dados

O banco de dados `acme`, localizado em `https://mysql.acme.com`, com *charset* `utf8`, usuário `gerente` e senha `g3ReNT&`, contém a tabela `fornecedor`, cuja estrutura é indicada abaixo:

```sql
CREATE TABLE fornecedor (
    id INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    codigo CHAR(8) NOT NULL UNIQUE,
    nome VARCHAR(100) NOT NULL,
    cnpj CHAR(14) NOT NULL UNIQUE,
    email VARCHAR(60) NOT NULL UNIQUE,
    telefone CHAR(11) NOT NULL
) ENGINE=INNODB;
```

### II. Classe `Fornecedor`

Considere a classe `Fornecedor`, do arquivo `fornecedor.php`:

```php
<?php
namespace acme;

class Fornecedor {
    public int $id = 0;
    public string $codigo = '';
    public string $nome = '';
    public string $email = '';
    public string $cnpj = '';
    public string $telefone = '';

    public function __construct( array $dados = [] ) {
        $this->id = valor( $dados, 'id', 0 );
        $this->codigo = valor( $dados, 'codigo', '' );
        $this->nome = valor( $dados, 'nome', '' );
        $this->cnpj = valor( $dados, 'cnpj', '' );
        $this->email = valor( $dados, 'email', '' );
        $this->telefone = valor( $dados, 'telefone', '' );
    }
}

function valor( array $a, $chave, $default ) {
    return htmlspecialchars( isset( $a[ $chave ] ) ? $a[ $chave ] : $default );
}
```

### III. Exceção e interface do repositório

Considere a classe e a interface abaixo, ambas do arquivo `repositorio-fornecedor.php`:

```php
<?php
namespace acme;

require_once 'fornecedor.php';

class RepositorioException extends \RuntimeException {}

/** Todos os métodos devem lançar apenas a exceção do tipo RepositorioException. */
interface RepositorioFornecedor {
    /** Retorna um array de objetos de Fornecedor. */
    function todos( string $filtro = '' );

    /** O fornecedor recebido deve ganhar o ID gerado pelo meio de persistência. */
    function cadastrar( Fornecedor &$fornecedor );

    /** O ID do fornecedor não deve ser atualizado. */
    function atualizar( Fornecedor $fornecedor );

    /** Remove pelo id ou pelo código. */
    function remover( string $idOuCodigo );
}
```

Implemente uma API RESTful, com ponto de entrada em um arquivo `index.php`, que disponibilize o recurso `/fornecedores`, em que seja possível:

### a) Consulta - 2,0 pontos

Consultar todos os fornecedores que contenham, em qualquer um de seus campos, o conteúdo do parâmetro `filtro` fornecido para a URL.

Exemplo:

```text
/fornecedores?filtro=Xpto
```

Se o parâmetro não for informado ou se seu valor estiver vazio, todos os fornecedores devem ser retornados. Os fornecedores devem ser retornados em formato JSON.

### b) Cadastro - 2,0 pontos

Cadastrar um fornecedor, recebendo os dados no formato de URL codificada (`x-www-form-urlencoded`).

### c) Atualização - 2,0 pontos

Atualizar um fornecedor específico, identificado na URL pelo `id`, sem usar parâmetros, recebendo os dados no formato JSON.

Exemplo:

```text
/fornecedores/10
```

### d) Remoção - 2,0 pontos

Remover um fornecedor específico, identificado na URL pelo `id` ou pelo `codigo`, sem usar parâmetros.

Exemplos:

```text
/fornecedores/10
/fornecedores/AX-98.kf
```

Veja o formato do campo `codigo` abaixo.

### Requisitos adicionais

Para isso, é preciso:

- retornar os códigos de status HTTP e cabeçalhos mais apropriados para cada caso, inclusive quando o recurso requisitado não for encontrado;
- utilizar o banco de dados indicado anteriormente, através de uma implementação da interface `RepositorioFornecedor`, observando o comportamento descrito em seus comentários;
- em uma função própria, validar os dados de um `Fornecedor`, tanto para o cadastro quanto para a alteração, retornando de uma só vez todos os problemas encontrados, caso haja, conforme as regras a seguir:
  - cada atributo de `Fornecedor` deve respeitar os limites mínimo e máximo indicados nos campos da tabela fornecida;
  - o `id` deve ser um número inteiro e não pode ser negativo;
  - **0,5 ponto:** o `codigo` deve ter, nesta ordem, duas letras maiúsculas, traço, dois números, ponto e duas letras minúsculas, como `AX-98.kf`. Utilize uma expressão regular para validá-lo;
  - o telefone e o CNPJ só devem conter caracteres numéricos.

> **Dica:** considere criar funções adicionais que agilizem a validação de coisas repetitivas.
