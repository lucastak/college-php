## Questão 2 — 4,0 pontos

Considere o banco de dados MySQL de nome `p1` localizado no endereço IP `192.168.0.1` com caracteres no formato `utf8`, usuário `dev` e senha `pHp_d3V`, com a estrutura a seguir:

```sql
CREATE TABLE produto (
    id         INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    descricao  VARCHAR(100) NOT NULL UNIQUE,
    preco      DECIMAL(10,2) NOT NULL
) ENGINE=INNODB;

CREATE TABLE setor (
    id      INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    codigo  CHAR(3) NOT NULL UNIQUE,
    nome    VARCHAR(30) NOT NULL UNIQUE
) ENGINE=INNODB;

CREATE TABLE estoque (
    id          INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    produto_id  INT NOT NULL, -- chave estrangeira
    setor_id    INT NOT NULL, -- chave estrangeira
    quantidade  INT DEFAULT 0,
    CONSTRAINT unq_estoque UNIQUE (produto_id, setor_id),
    CONSTRAINT fk_estoque__produto_id FOREIGN KEY (produto_id)
        REFERENCES produto (id) ON UPDATE CASCADE ON DELETE CASCADE,
    CONSTRAINT fk_estoque__setor_id FOREIGN KEY (setor_id)
        REFERENCES setor (id) ON UPDATE CASCADE ON DELETE RESTRICT
) ENGINE=INNODB;
```

Como pode ser observado no banco de dados, há uma tabela "estoque" que mantém o estoque de cada produto por setor. Por exemplo, o produto "Chocolate Acme" pode ter quantidade 30 no setor "Estoque" e quantidade 5 no setor "Prateleira".

**Faça um programa** que realize o cadastro de um produto, no banco de dados acima, solicitando do usuário: **descrição, preço e quantidade** do produto, além do **código do setor** (não é o id!) em que essa quantidade deve ser cadastrada.

**Validações necessárias:** A descrição deve ter de 2 a 100 caracteres; o preço deve ser um número e deve ser no mínimo R$ 0,50 (cinquenta centavos); a quantidade deve ser um número e deve ser no mínimo 1; o código do setor deve ter 3 caracteres e o setor deve existir. Utilize controle de transação e trate exceções adequadamente.

## Questão 3 — 4,0 pontos

Considere o arquivo `RepositorioException.php` abaixo:

```php
<?php
namespace repositorio;
class RepositorioException extends \RuntimeException {}
```

Considere o arquivo `Produto.php` abaixo, **sem namespace**:

```php
<?php
class Produto {
    public $id, $descricao, $preco, $numeroSetores, $totalEstoque;
    public function __construct(
        $id = 0, $descricao = '', $preco = 0, $numeroSetores = 0, $totalEstoque = 0
    ) {
        $this->id=$id; $this->descricao=$descricao; $this->numeroSetores=$numeroSetores;
        $this->totalEstoque=$totalEstoque;
    }
}
```

Considere `RepositorioProdutos.php`, **observando atentamente todos os seus comentários**:

```php
<?php
namespace repositorio;

/** Repositório de Produtos. Apenas lança RepositorioException em seus métodos. */
interface RepositorioProdutos {

    /** Retorna um array de objetos da classe Produto.
        Cada produto deve conter o número de setores em que possui estoque e
        a quantidade total em estoque (soma da quantidade em todos os setores). */
    public function todos();

    /** Aumenta a quantidade em estoque de um certo produto em um certo setor. */
    public function aumentarEstoque( $idProduto, $idSetor, $quantidade );
}
```

Crie a classe `RepositorioProdutosEmBDR`, em um arquivo PHP homônimo e no **namespace `App`**, que implemente a interface acima para manipular produtos no banco de dados relacional `p1`, informado anteriormente, utilizando PDO. Somente permita que seja lançada a exceção `RepositorioException` nos métodos. A classe **não deve instanciar PDO** (direta ou indiretamente) e **não deve utilizar métodos de impressão** (como `echo` ou `die`). O método `todos()` deve usar funções de agregação do SQL para calcular o número de setores e o total em estoque, para cada produto. Não esqueça de incluir todos os arquivos PHP necessários e utilizar os namespaces corretos na implementação.
